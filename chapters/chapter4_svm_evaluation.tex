\chapter{SVM Classifier Evaluation}

\section{Experimental Setup}

We evaluated the Support Vector Machine (SVM) classifier on the GSE42568 breast
cancer dataset (121 samples: 104 cancer, 17 normal) using a 5-fold stratified
cross-validation strategy to prevent data leakage. The evaluation followed the
same dual-track design as the project pipeline:

\begin{itemize}
    \item \textbf{Path A (Baseline):} Train the SVM on all preprocessed features
          without feature selection.
    \item \textbf{Path B (Optimised):} Apply a feature-selection method inside
          each training fold before fitting the SVM.
\end{itemize}

All models used a linear kernel and balanced class weights. The feature-selection
methods used in Path B were the same ones implemented in the project scripts:
Welch's t-test, ANOVA, SVM-RFE, Random-Forest importance, and LASSO. The main
change from the earlier workflow is that the filter methods now follow an
explicit p-value-based selection rule, while the wrapper methods use an ANOVA
prefilter inside each training fold. The GSE42568 run reported here was executed
without an explicit p-value cutoff in the CLI, so the current outputs reflect
the default top-$k$ behavior (20 features) rather than a threshold-driven subset.
Once a suitable $\alpha$ has been chosen, the feature-selection pipeline should
be rerun with the corresponding CLI argument to obtain p-value-based filter
selections.

\section{Path A: Baseline Track Results}

The baseline SVM trained on the full feature set failed to learn a stable
classification boundary. The model collapsed to the majority class, so accuracy
appeared high only because cancer samples dominated the dataset. In this setting,
Matthews correlation coefficient (MCC) is a more informative metric than raw
accuracy because it penalises trivial majority-class predictions.

The result illustrates the core difficulty of this problem: with many more probes
than samples, the SVM has too much noisy high-dimensional input and too few
minority-class examples to recover a meaningful separating hyperplane without
feature selection.

\section{Path B: Optimised Track Results}

The Path B experiments show that feature selection changes the geometry of the
classification problem before the SVM is trained. The most important qualitative
outcome is that the selected-feature variants are more informative than the
original full-space baseline, even when the class imbalance remains severe.

\subsection{Filter Methods}

The filter selectors rank probes according to statistical evidence. In the updated
implementation they can either retain features below a user-defined p-value
threshold or use a compact top-$k$ rule. This means that the number of retained
features is not fixed in advance when a p-value threshold is used. In practice,
a permissive threshold can leave a very large number of probes, whereas a stricter
threshold produces a smaller subset.

This design makes the filter stage transparent and efficient. It is especially
useful for rapid screening, although it does not explicitly model interactions
among features.

\subsection{Wrapper Methods}

The wrapper methods do not operate on the full 54,675-probe matrix directly.
Instead, they use an ANOVA-based prefilter inside each training fold to remove
weak univariate signals before the actual wrapper search begins. This has three
practical effects: it makes the search computationally feasible, it removes
obviously irrelevant probes, and it improves the stability of the ranking step.

The retained wrapper methods are SVM-RFE and Random-Forest importance. They are
more expensive than the filter methods, but they search more complex feature
combinations and are therefore better suited to the multivariate structure of the
problem.

\subsection{Embedded Method}

LASSO provides an embedded sparse solution. It is especially useful when the goal
is interpretability, because the penalty shrinks many coefficients to zero and
leaves a compact set of informative probes. Its behaviour depends on the chosen
regularisation strength, but it remains one of the most practical embedded
options for this high-dimensional setting.

\section{Why the Prefilter Is Still Useful}

The prefilter remains important because it reduces the candidate set before any
wrapper algorithm is applied. This is beneficial for three reasons: it makes the
wrapper search computationally tractable, it removes probes with weak univariate
signal, and it reduces the risk of unstable rankings in a very large feature
space. The prefilter is computed only from the training fold, so the evaluation
remains unbiased and leakage-free.

\section{Discussion}

The GSE42568 experiment is valuable because it demonstrates a common pattern in
molecular classification: a severe class imbalance combined with an extremely
large feature-to-sample ratio can make the raw SVM nearly useless. Feature
selection is therefore not a cosmetic refinement but a necessary step for
recovering a model that learns something meaningful. The updated implementation
makes this explicit by separating the selection logic from the classifier and by
allowing the user to choose either p-value-driven filter subsets or compact
wrapper and embedded subsets depending on the analytical goal.
